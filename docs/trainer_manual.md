# 讲师手册

## 课前准备

1. 用干净 Python 3.9+ 环境执行 `pip install -r requirements.txt` 与 `pytest -q`。
2. 确认 Notebook 可启动；准备无 API key 的离线路径。若客户要求模型比较，必须使用客户授权密钥、同一 prompt、同一数据与明确预算。
3. 提前确认禁入数据：个人信息、密钥、未脱敏工单、内部文档不得复制到公共服务。
4. 收集两个客户场景，但不承诺课堂内完成生产集成。

## 教学节奏

每个 Lab 采用 10 分钟概念、15 分钟代码、20 分钟结对练习、10 分钟测试复盘。先运行已有代码，再修改；先展示失败测试，再展示修复。英文术语第一次出现时给出中文解释，代码标识保持英文。

## 讲解重点

- Prompt：强调评测集，不展示“神奇咒语”。显式步骤用于可审计流程，不要求模型泄露隐藏思维链。
- Structured Output：Schema 是系统边界；解析失败必须进入可观察的错误路径。
- Tool Calling：模型只能提议，应用负责授权与执行；数据库示例只读。
- RAG：先讨论检索证据，再讨论生成；没有证据就拒答。
- Agent Loop：每一步有预算、trace、停止条件与工具白名单。

## 常见问题处理

API key 缺失时继续离线 Lab，不在屏幕共享中配置真实密钥。依赖安装失败时运行 `.py` 导出版本并使用标准库答案。练习提前完成的小组增加边界测试；进度慢的小组只完成核心题，不跳过测试。

## 复盘与验收

最后要求每组展示一条成功 trace、一条安全拒绝、一个自动测试和一项上线风险。记录未解决问题与负责人。避免将训练结果描述成生产就绪、准确率保证或合规认证。
